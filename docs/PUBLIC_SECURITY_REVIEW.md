# Public material security review

Review date: **2026-10-27**. Reviewed source: RC3.3 `49693b3`; this review makes no production changes and does not validate credential liveness.

## Scope and method

Inspected tracked HTML/JavaScript, workflow JSON (including Code, HTTP parameters, credentials and pin data), documentation, environment examples, SQL/ACL outputs, test/demo fixtures, integration evidence, proxy configuration and credential references. Fetched advertised origin branches and all available pull-request head refs, then scanned **52 reachable commits / 283 unique reachable blobs**. Included earlier versions and material on other fetched branches, not only the current checkout.

A local Python scan over `git rev-list --objects --all` and `git cat-file --batch` searched provider/GitHub token formats, private-key blocks, JWTs, literal bearer values, password-bearing URLs, and credential assignments. Follow-up inspection covered German username/password configuration and candidate assignment context. The scan reported locations and categories only; candidate values were not printed in the review. **71 blob/category candidate entries** were reviewed as fixtures, placeholders, interpolation, or code expressions; no confirmed production credential was identified. The reference HTML username/password fields are empty in reachable versions. Workflow credential ID/name references are not decrypted secrets; reviewed current exports contain no pinned execution data.

Also retrieved public GitHub text through the repository API: **27 issues/PR records (open and closed), 19 issue/PR comments, 0 inline review comments, and 0 releases/assets** at review time. The Actions API also returned 0 workflow runs and 0 artifacts; no image/attachment references were found in retrieved issue/PR/comment bodies. Provider-token/private-key/password-URL checks found no confirmed secret there. This is a snapshot, not continuous monitoring.

Scope limits: unreachable/deleted Git objects, forks, external linked pages, image-only screenshots/attachments, cached archives and private infrastructure were not comprehensively retrievable/scanned. Referenced services were not probed and no credentials were tested. Pattern scanning and manual review cannot prove the absence of an arbitrary or unknown-format secret. Original unconditional statements such as “no real secrets were committed” should be read as historical claims, not a security guarantee.

## Historical exposure: separate assessment

**Confirmed historical production secret exposure: none identified within the reviewed scope.** Known synthetic credentials, operational metadata, and contact addresses exist in public history and remain accessible. Deleting a current file would not erase them. There is no evidence here establishing that fixture values were ever used in production; reuse must be checked by the Owner privately.

If the Owner discovers that any published sample/log value was a real credential, assume historical exposure: revoke or rotate it at the issuing service, invalidate affected sessions where appropriate, review audit/usage logs, and inspect dependent systems. Do not paste the value into an issue or PR. Record only the type, affected path/commit, exposure window, and remediation status in public findings.

History removal is a separate Owner decision after revocation; it cannot recall forks, downloads or caches. **No history rewrite is authorized or performed by this task.** No existing credentials were changed. Contact-data exposure calls for an Owner retention/consent decision rather than automatic credential revocation.

## Positive controls and remaining verification

The current gateway separates form/admin scope; enforces exact Origin on mutations; uses signed HttpOnly cookies; limits request/response sizes; restricts AI upstreams; and sanitizes responses. The database adapters bind parameters, and the snapshot path is read-only with certificate verification. CRM mutations use explicit functions and preserve audit data. Adapted WF-08 uses a narrower context function/role and validates values/citations; RC3.3 verifies published executable properties.

These controls are implemented and selectively tested, not a comprehensive penetration test or production assurance. Effective database memberships, PUBLIC privileges, function owners/search paths, deployed TLS/headers, per-instance logging and real provider settings still require target-specific verification. See [project status](PROJECT_STATUS.md) for evidence boundaries. No database script, deployment helper, workflow import, activation, email send or infrastructure command was executed for this review. `npm audit --prefix gateway --json` reported zero known vulnerabilities in the locked dependency set on the review date; this is advisory coverage, not proof against unknown vulnerabilities.
